# v1.3.6

本版本新增 Prometheus 时序指标接口，支持按项目、应用和环境定位发布与业务状态，并在系统设置中控制指标访问鉴权。

## 新增

- 统一 `GET /metrics`，输出项目和应用元信息、发布单状态、累计创建次数、CI/CD 执行结果与耗时分布、最近部署成功时间、审批积压及 Agent 状态。
- 发布业务状态与页面复用同一套阶段推导规则，明确区分构建、部署、审批拒绝、取消和跳过。
- 持久化指标事件与业务操作在同一事务提交，重复追踪不会重复计数，删除发布单或重启服务后保留累计计数与耗时分布。
- 后台聚合并缓存指标，抓取请求不访问业务数据库或外部业务源；采集失败保留上次成功值，并暴露采集健康与新鲜度。
- 支持将 HTTP JSON 业务数据映射为带应用、环境和数据源标签的 `biz_` Gauge / Counter。
- “系统设置 → 系统管理 → 指标访问”增加“指标访问鉴权”开关：开启时校验独立采集 Token；关闭时无需登录或 Token，直接访问指标。保存后当前实例立即生效，重启后保留，其他副本每 5 秒同步。
- Docker 环境变量、Nginx 指标代理、Prometheus 抓取与告警示例，以及 Grafana 查询说明。
- 界面版本号与前端包版本统一，由包版本自动显示 `v1.3.6`。

## 升级与配置

- 启动时自动创建指标事件表、补充索引并幂等回填历史记录；首次抓取形成累计基线，无法还原启用前的时序曲线。升级前按现有流程备份数据库。
- 指标接口通过 `metrics.enabled` 或 Docker 的 `GOS_METRICS_ENABLED` 启用。非本地环境未保存过鉴权设置时，默认要求鉴权；可设置 `GOS_METRICS_BEARER_TOKEN`，或登录系统设置明确关闭鉴权。
- HTTP JSON 业务源通过 `metrics.business_sources` 或 `GOS_METRICS_BUSINESS_SOURCES` 配置，未接入的数据不会输出演示数值。
- 本次 GitHub 发布包含源码与说明。README 的预构建镜像示例仍指向已发布的 `v1.3.5`；本版本可通过源码构建镜像。
